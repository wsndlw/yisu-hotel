# P0 初始里程碑与负责人矩阵

## 1. 角色与具名负责人

本项目采用单人多职执行模式：厉飞雨兼任 PO、BE、FE、QA、OPS 和 SEC。该模式不豁免独立评审；P0 基线、数据库迁移和安全放行必须由非作者、非项目执行人的独立评审人复核。

| 角色代码 | 职责 | 负责人 | 代理人 |
|---|---|---|---|
| PO | 范围、业务规则、优先级与变更批准 | 厉飞雨 | 可空 |
| BE | Python 架构、实现、数据迁移与后端质量 | 厉飞雨 | 可空 |
| FE | PC/移动端契约盘点、环境改造与双端回归 | 厉飞雨 | 可空 |
| QA | 测试策略、契约/E2E/并发验收和证据归档 | 厉飞雨 | 可空 |
| OPS | CI、容器、配置、备份、发布与回滚 | 厉飞雨 | 可空 |
| SEC | 威胁评审、密钥、依赖和安全测试 | 厉飞雨 | 可空 |
| IR | 独立检查范围、ADR、风险、版本控制和门禁证据 | 待指定（必须独立） | 可空 |

RACI：`A` 最终负责，`R` 执行，`C` 参与评审，`I` 被通知。每项只能有一个 `A`。

在单人模式下，RACI 表示同一执行人在不同阶段切换职责视角，不代表存在职责隔离。执行人的多角色签字属于自审，不能替代 IR。每个阶段必须保留自动化门禁、书面证据和适用的独立评审记录。

## 4. 发布责任边界

- 本轮只做到“准上线”，不执行生产发布。
- 未来发布中，OPS 是唯一切流执行责任人；PO 是业务放行人；QA 是质量放行人；BE 是迁移和应用健康责任人。
- 任一放行人拒绝或门禁证据缺失时不得继续切流。
- 回滚不需要等待常规变更会议，但必须由 OPS 执行并在事后补齐记录。

## 5. 分支与评审基线

- 采用短生命周期功能分支和 Pull Request；主分支受保护，禁止直接推送。
- 至少需要一名非作者评审；数据库、安全、GraphQL 契约变更需相应责任角色参与。
- P0 的独立评审是恢复 P1 的前置硬门禁，最迟介入点为 P1 继续采集运行时契约快照之前。
- 合并前必须通过当阶段已启用的格式、静态检查、类型、测试、依赖和构建门禁。
- 紧急修复仍通过 PR，允许先止血后在 24 小时内补齐常规证据。
