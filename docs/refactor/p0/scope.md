# P0 范围清单与非目标

## 1. 判定标签

- **迁移**：在 Python 后端重建，并纳入本轮验收。
- **保留**：保持对外契约或用户可观察语义，不重写对应前端业务流程。
- **删除**：有意移除的危险行为或无效实现，不作为兼容目标。
- **延期**：明确不在本轮实现，新增需求需走变更流程。

## 4. 对外兼容边界

以下内容冻结为兼容基线：

- `/graphql` 路径。
- Query、Mutation、输入/输出类型、字段名、枚举文本、nullable 规则。
- `{ code, message, data }` 包装结构及当前直接返回实体的 operation。
- `Authorization: Bearer <token>`。
- 数据库已有 UUID、外键标识和业务 ID。
- 金额在 GraphQL 边界以人民币元和现有 `Float` 字段返回。
- 日期字段继续使用当前 `YYYY-MM-DD` 或 Schema 中声明的 ISO 8601 DateTime。

以下行为是已批准修正，不得当作兼容要求：

- 公开注册或邮箱注册时创建 `ADMIN`。
- 默认 JWT 密钥、硬编码数据库账号和生产宽松 CORS。
- TypeORM `synchronize: true` 自动改表。
- 明文持久化/输出验证码，或在日志记录验证码、JWT、密码和 OSS 密钥。
- 无超时的外部请求、Web 请求内同步重试邮件。
- 未校验状态转换、归属关系或请求幂等性造成的越权和重复写入。
- 管理仪表盘中的随机/演示数据；字段保留，但必须改为真实统计或明确的空值语义。

所有兼容差异必须在 P1 建立快照，在 P9 达到“未批准差异为 0”。

## 5. 非目标与延期项

| 项目 | 决议 | 重新进入条件 |
|---|---|---|
| RESTful 全量替换 GraphQL | 延期 | 独立 ADR、前端改造预算和版本化迁移计划获批 |
| 更换 MySQL 为 PostgreSQL/其他数据库 | 延期 | Python 领域服务稳定后独立立项 |
| 微服务拆分 | 延期 | 团队规模、流量或独立伸缩需求有数据支持 |
| 真实支付与退款 | 延期 | 支付供应商、财务/合规和退款规则确认 |
| 发票、优惠券、客服 | 延期 | 产品立项并补充领域模型 |
| 大规模 UI/交互改版 | 延期 | 独立前端迭代 |
| 正式服务器购买、备案和生产切流 | 延期 | P11 完成并获得发布授权 |
| 生产数据复制到开发环境 | 删除 | 禁止；只允许脱敏抽样或合成数据 |
| 本轮新增业务功能直接插入开发 | 删除 | 必须执行 `change-control.md` |

## 6. 模块完成定义

模块只有同时满足以下条件才算“已迁移”：

- 对外 GraphQL 契约兼容或差异已经 ADR 批准。
- 成功、失败、权限、边界和并发/幂等测试通过。
- 数据模型由 Alembic 管理，无运行时自动改表。
- 日志、指标、请求 ID、敏感信息处理符合生产基线。
- 外部依赖具有超时、有限重试、fake 和降级策略。
- 对应文档、运行方式和回滚说明同步更新。
