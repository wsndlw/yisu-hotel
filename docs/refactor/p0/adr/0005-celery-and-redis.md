# ADR-0005：使用 Redis 与 Celery 处理短期状态和异步任务

- 状态：Proposed（技术基线候选，待独立评审）
- 日期：2026-10-07

## 背景

邮箱验证码当前明文保存在用户表并在 Web 请求内同步发送。生产环境还需要跨进程限流、一次性消费和可靠重试。

## 决策

Redis 用于验证码哈希+TTL、发送/登录限流、短期幂等辅助状态和缓存。Celery 以 Redis 为 broker/result backend，首批只承担邮件等允许重试的非核心副作用。

数据库交易事务不放入 Celery；订单和库存必须在同步请求的数据库事务内完成。任务按至少一次投递设计，必须具备幂等键、有限重试、退避和死信/失败可观测性。

## 后果

- 邮件故障不会长期占用 Web worker。
- 新增 Redis 可用性和任务重复执行风险，需要健康检查与降级策略。
- 测试环境必须提供 fake 邮件/OSS，不依赖真实账号。
